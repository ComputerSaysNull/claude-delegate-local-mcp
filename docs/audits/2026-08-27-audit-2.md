# Documentation audit — 2026-08-27 (second)

Supplements [the first audit of the same day](2026-08-27-audit.md); it does not replace it.
That one ran immediately after M3 merged and found two defects. This one was run on request
a few hours later, on the suspicion that two was too few for 3,900 lines of documentation.
It was: **nineteen findings, of which eighteen held.**

Scope: every hand-written document in both planes, the two generated ones, the ownership
manifest, the agent definitions, and the gate's own checks. Six audits ran in parallel over
disjoint scopes and every finding was re-verified against the source before landing here,
which mattered — three did not survive that check and are recorded at the bottom, because a
rejected finding is evidence about the audit method.

## The theme

Two fault classes account for fourteen of the eighteen, and the first audit found one
instance of each without recognising either as a class.

**A fact restated outside the document that owns it.** The first audit certified "no fact
found in two documents". There were six such facts. The measured bytes-per-token table alone
existed in six places, in copies that had already diverged.

**Machinery described in the present tense before it exists.** The first audit found one
(`thinking_token_budget`) and its own correction found a second (`scripts/release.py`)
without drawing the conclusion. There were seven more.

## Found and fixed

### Facts living in more than one place

1. **The bytes/token measurement, in six places** — `JOURNAL.md`, ADR-0019, `docs/AGENTS.md`,
   `CHANGELOG.md`, `PLAN.md`, and a comment in `config.py`. The copies had already diverged:
   ADR-0019 carried six rows, `docs/AGENTS.md` four, `JOURNAL.md` four *different* ones. A
   partial copy is worse than a full one, because it can drift without ever contradicting.
   `JOURNAL.md` now owns the complete six-row table and everything mutable links to it. The
   copies in ADR-0019 and `CHANGELOG.md` stay: both documents are append-only and their
   bodies are never edited, so those are dated records rather than live duplicates. Worth
   stating explicitly, because it is the only reason two copies survive.
2. **The reasoning-exhaustion measurement, in two places** — ADR-0014 and `docs/MODELS.md:65`
   both carried "roughly 15,600 characters". `MODELS.md` now cites the ADR. The first audit
   checked exactly this class, wrote "the max-effort measurement table lives only in
   `JOURNAL.md`", and generalised from one table to all of them.
3. **Two gate constants restated as prose.** `AUDIT_STALE_COMMITS` was lowered from 60 to 15
   on 2026-08-27; `PLAN.md:53` and `CONTRIBUTING.md:151` went on saying 60.
   `AUDIT_PRESSURE_THRESHOLD = 12` was restated at `CONTRIBUTING.md:150`. Both now describe
   the signal and name the file holding the number. Correcting 60 to 15 would have been the
   wrong fix: it leaves three copies that agree today. `CHANGELOG.md:167` already records
   that the *test* for this check had its own literal copy of the same number and was
   fixed — so the change was known to have copies, and two were missed anyway.
4. **`README.md:146` named the generated file as the source of truth** — "No configuration
   default is stated anywhere but `docs/CONFIGURATION.md`". That file is a rendering; a
   reader following the README edits the artefact and loses the edit. Now names `config.py`.

### Machinery described before it exists

5. **`docs/CONFIGURATION.md` rendered 19 settings that nothing reads.** The sandbox knobs,
   the model-facing tool limits, admission control — a third of the reference — presented
   identically to settings that work. Worse than documentation: `config.py` *validates* them
   at load, so the server can refuse to boot over `DELEGATE_RUN_BASH_TIMEOUT=0` while
   `run_bash` does not exist. The file is generated, so the defect was in the generator. It
   now computes the marker by scanning the source for readers rather than carrying a
   hand-kept list, which would be a second copy of `PLAN.md` and would rot the day a
   subsystem landed. The count is measured, not asserted: 19. Five negative tests in
   `tests/regression/test_inert_settings_are_marked.py`, including one proving the marker
   *can* vanish — a marker that cannot clear is a stale list by another name.
6. **`docs/TROUBLESHOOTING.md` indexed nine symptoms that cannot occur** — `turn_limit`, the
   whole Sandbox section, malformed tool arguments, both progress-notification timeouts.
   Verified absent: no `turn_limit` anywhere in `src/` or `tests/`, no progress notification
   in `server.py`. Unlike `docs/AGENTS.md`, which declares its scope in a banner at line 11,
   this document declared nothing, so a reader could not tell an entry describing today from
   one describing M5. The entries are worth keeping — they are the index ready for when the
   code lands — so they are marked rather than deleted, and the file now says what the mark
   means. Budget raised 270 → 290, reason recorded in the file.
7. **`CHANGELOG.md:8` promised a citation no entry carries.** The declared format is
   `- YYYY-MM-DD (#PR) what changed, and why.` Zero of fifty entries have a `(#PR)`. The
   sharpest finding of the audit is *why*: the entry at lines 144-153 — the one announcing
   the fix for describing `scripts/release.py` in the present tense — says "The PR number
   survives the squash and is written by hand in the same edit as the entry", describing in
   the present tense a practice that has never once been applied. A fix that reintroduced
   its own bug, in the same file, in the same commit. The format line now says the
   convention starts with entries written after 2026-08-27.
8. **Two `CLAUDE.md` invariants written in the present tense about unwritten code** —
   "`paths.py` and `sandbox.py` are independent layers" (`sandbox.py` is M5) and
   "`allowed_tools` is enforced at two sites" (zero sites exist). Both are worth
   pre-registering for whoever writes the code; both now say so instead of implying the code
   is already there to check.

### Wrong claims

9. **ADR-0005's portability claim is false, and `docs/AGENTS.md:22` repeated it.** "The files
   use the same format Claude Code already uses for its own subagents, so they are portable."
   This repository's own `.claude/agents/*.md` are the counter-example: Claude Code spells
   the tool list `tools`, this format spells it `allowed_tools`; Claude Code accepts
   `effort: medium`, which `config.py` refuses on purpose. ADR bodies are never edited, so
   this could not be fixed in place: **ADR-0031** records the correction, ADR-0005's heading
   becomes *Partially superseded*, and `AGENTS.md` now says borrowed rather than portable.
10. **`docs/AGENTS.md:7` linked to `docs/TOOLS.md`, which does not exist.** The first audit
    checked this exact question and wrote "nothing references it as existing" — true of the
    prose, which hedges with *(generated, once the tools exist)*, and false of the link
    beside it. Now plain text.
11. **`docs/ARCHITECTURE.md` used one marker for two meanings, four rows apart.** In the
    module table, `*(not built)*` scopes to a trailing clause on `context.py` and `loop.py`
    but to the whole module on `tools.py` and `sandbox.py`. The evidence that this misleads
    is that it misled this audit: two agents read the table and disagreed about which modules
    exist. Now says which it means.
12. **The `docs-audit` agent's own output examples cited real coordinates.** Its format
    sample listed `src/claude_delegate_local/agents.py:41` (no such file) and
    `docs/MODELS.md:60-74` as "three paragraphs restating one table" — those lines are the
    `default_effort` prose. A sample that reads as a findings list, in the file that teaches
    agents what a finding looks like. Now fictional paths, with a line saying why.

### Gaps in the machinery

13. **Six gate checks have no negative test** — `check_budgets`, `check_orphan_docs`,
    `check_manifest_docs_exist`, `check_split_dodge`, `check_secret_paths`, `check_pr_text`.
    `tests/regression/test_gate_self_defeating_checks.py` covers the four bugs already found,
    by name; its own docstring says both were found "by negative-testing the gate rather than
    by reading it", which is exactly what these six have not had. `check_pr_text` and
    `check_secret_paths` guard the public surface `CLAUDE.md` says no hook can gate.
    **Not fixed here** — see below.
14. **The manifest justified one phantom claim and not its twin.** A comment explains why
    `docs/AGENTS.md` keeps its claim on the unwritten `agents.py`; nothing explained
    `docs/ARCHITECTURE.md`'s identical claim on the unwritten `sandbox.py`, leaving a reader
    unable to tell a deliberate placeholder from a mistake. Comment added; the claim stays,
    because dropping it would throw away the only thing that will force the document to be
    updated when the module lands.
15. **`ARCHIVE-AT: 700` warned about a procedure that existed nowhere.** `CHANGELOG.md` is
    619 lines and the gate will eventually tell someone to "split the older entries into a
    dated file" with no document saying where. The destination was implicit in the gate all
    along — `check_budgets` skips any path containing an `archive` component — so
    `CONTRIBUTING.md` now documents it.

### Smaller

16. `docs/TROUBLESHOOTING.md:171` stated a value ("milliseconds, minimum 1000") for Claude

17. `CONTRIBUTING.md` did not say what happens when a second audit runs on a date already
    used. It does now, which is why this file is `-2` and supplements rather than replaces.
18. `JOURNAL.md`'s copy of the ratio table — the one now promoted to owner — was itself

## Found and deliberately not fixed

**The six checks without negative tests (finding 13).** Writing them changes the gate's test
suite, not the documentation, and each needs a real violation constructed and proven to
fire — `check_pr_text` in particular needs a synthetic event payload. Bundling six
security-relevant tests into a documentation commit makes both harder to review. They want
their own commit, and it should come before the next milestone rather than after.

## Withdrawn on verification

Recorded because the method is what produced them, and a method that reports only its hits
cannot be assessed.

- **"`CHANGELOG.md` is missing `BUDGET-PER-ENTRY`."** It is, and it should be:
  `check_budgets` splits on `^## `, and this file's only `##` section is `[Unreleased]`, so
  the marker would block on a 600-line "entry" immediately. Its entries are bullets, not
  sections. `ARCHIVE-AT` is the right instrument and it already has it.
- **"`docs/AGENTS.md` documents frontmatter that contradicts `.claude/agents/*.md`."** Filed
  as a blocker; it conflated two systems. `docs/AGENTS.md` documents the delegate server's
  format (M6, unbuilt, and declared as such); `.claude/agents/` holds Claude Code's own
  subagents, owned by `CONTRIBUTING.md`. The effort levels it flagged as undocumented are
  `config.py:31`'s deliberate set. Rejecting it is what surfaced finding 9, the real defect
  underneath.
- **"`context.py` and `loop.py` are marked not built but exist."** A misreading of the
  scoping described in finding 11 — and the second reader to make it, which is what turned
  an apparent non-finding into a real one.

- All ADRs have status headings, no numbering gaps, no edited bodies in `git log -p`.
- No `Docs-Gate-Skip` trailer anywhere in history; nothing to audit for abuse yet.
- No head-node address, `host:port` shape or personal identifier in any tracked markdown.
- `docs/MODELS.md` matches `registry.py` field for field, and already marked its one unbuilt
