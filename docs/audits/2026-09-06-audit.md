# Documentation audit — 2026-09-06

Raised by the gate: 38 commits since `docs/audits/2026-09-03-audit.md`. No per-document
drift warning fired; the pressure was global.

Scope: every hand-written document in both planes, plus `config.py`, `tools.py`,
`registry.py`, `agents.py`, `paths.py`, `loop.py`, `backends/**`, `sandbox.py`,
`admission.py`, `slots.py`, `transcript.py`, `server.py`, `context.py`, `wsl.py`,
`install_hooks.py`, `.github/workflows/ci.yml` and `scripts/docs_ownership.toml`.
Delegated to the local model, one check class per call.

**TOO VERBOSE was not run and this audit does not cover it.** Six of the seven classes are
covered; the seventh needs a reading of 1,457 lines with a trim proposal per candidate, and
was deferred rather than done badly.

`docs/AGENTS.md` against `agents.py` was done in the main conversation, after the delegated
pass returned empty twice — once as a five-part question and once narrowed to frontmatter
alone, at 41,831 and 41,364 output tokens with `finish_reason: "length"` and
`reasoning_exhausted: true` both times. Its sibling over the *larger* `paths.py` answered in
one turn, so this is not input size: the frontmatter comparison is a long list of small
enumerable items and the model spends its whole reply budget enumerating.

**Every finding was re-verified against source before being written down**, and that
changed two of them. One was retracted outright (see *Retracted*), and one clean verdict
rested partly on a section heading that does not exist. Both are recorded because an audit
whose verification never overturns anything is not verifying.

## Findings

1. [BLOCKER] `docs/DISPATCH.md` — "The last turn is declared **with no tools at all**" and
   "Withdrawing the tools leaves the model one thing it can still do". `loop.py` sends
   `tools=specs, tool_choice="none" if _final else "auto"`, and its comment says "Always
   offered, and forbidden rather than withdrawn on the final turn (ADR-0057)". The stale
   phrasing recurred in four passages while the document **already stated the correct
   mechanism** in "Turns, and what ends them" — added by the same commit that raised this
   document's budget for exactly that change. A reader trusting the stale half would
   restore an edit ADR-0057 measured as taking a 99.3% cache hit to 0.0%, on the one turn
   that must also fit a whole answer inside one deadline. Fixed.

2. [BLOCKER] `CONTRIBUTING.md` — "Run at most five agents concurrently; CI enforces it via
   `max-parallel`." Nothing in CI constrains agent concurrency. `max-parallel: 5` sits in
   the `tests` job strategy over a matrix of two entries, so it cannot bind, and `ci.yml`'s
   own comment is honest that it is applying the *number* "wherever it can be
   machine-enforced rather than merely written down". This one has already cost: the
   session that ran this audit fanned out twelve concurrent delegations, five of which died
   at the admission wall. Fixed by stating that the rule is a convention nothing enforces —
   and the rule's number moved from five to six, which is what the serving stack admits and
   what the registry entry already claimed.

3. [MAJOR] `docs/ARCHITECTURE.md` — the module table called `server.py` "the six tool
   declarations". There are five. **This row has now drifted twice in opposite
   directions**: the 2026-09-03 audit corrected it from five to six when ADR-0042 added a
   sixth, and ADR-0051 then removed both batch tools. A hand-maintained count against a
   decorator list is the wrong shape for this cell — worth generating or dropping the
   number, and recorded here rather than acted on. Fixed to five.

4. [MAJOR] `docs/ARCHITECTURE.md` — "So `run` walks the bound HOME and workdir". The secret
   scan walks three roots: `discover_secret_shadows` builds `roots = [req.home]`, appends
   `req.workdir`, then extends with `req.extra_binds`. The document contradicted itself —
   its "Why bubblewrap" section already said "covers all three roots rather than the two it
   began with". Fixed.

5. [MAJOR] `docs/DISPATCH.md` — "Only named metrics are read, and of their labels only
   `reason`". Four labels are read: `reason`, plus `kv_cache_size_tokens`,
   `num_gpu_blocks` and `enable_prefix_caching` from `vllm:cache_config_info` via
   `_CACHE_CONFIG`. The next sentence, which names that metric as a labels risk, was
   already inconsistent with the claim. Fixed.

6. [MAJOR] `docs/DISPATCH.md` — "Four of the five bugs this cost the ancestor project were
   one shape — a threshold computed against the wrong denominator." The project's own
   `docs/reviews/upstream-review-2026-08-26.md` enumerates all five, and at most two fit
   that shape: the flat reserve exceeding 95% of a small window, and the auto-probe reading
   the architecture maximum instead of the configured value. Bugs 1 and 5 are a wrong
   trigger case and a gate scope, not denominators. The review's own summary offers "the
   denominator is the thing to test" as advice, not as a count. Fixed to two.

7. [MINOR] `CLAUDE.md` ↔ `docs/AGENTS.md` — the hostname-versus-address *mechanism* stated
   in both. Trimmed to the rule, the consequence and a pointer.

8. [MINOR] `CLAUDE.md` ↔ `docs/AGENTS.md`, `docs/ARCHITECTURE.md` ×2 — the two-site
   `allowed_tools` rationale. One sentence, "a model can call a tool it was never offered",
   appears five times across four documents; `docs/TOOLS.md`'s copy is generated from the
   tool description and is legitimate, the other four are hand-written. `CLAUDE.md` is
   itself one of them, two sections after warning that duplication "is exactly how the
   project this descends from ended up documenting one setting three different ways".
   Trimmed in `CLAUDE.md` to the maintenance trap, which only it states.

9. [MINOR] `CLAUDE.md` ↔ `docs/ARCHITECTURE.md` — which tool each of the two layers governs,
   stated in both. Trimmed to the trap and a pointer.

10. [MINOR] `docs/CONFIGURATION.md` ↔ `docs/ARCHITECTURE.md` — the `sandbox_max_processes`
    rationale in both, the generated copy coming from `config.py`'s field description.
    Split rather than deleted: the table keeps constraints on the *value* (0 disables,
    below roughly 64 nothing starts), because that is what someone choosing a number needs
    in front of them, and `ARCHITECTURE.md` keeps how the cap is shared and how it fails.
    Fixed in `config.py`, table regenerated.

11. [MINOR] `README.md` — restated the bubblewrap-refusal mechanism and the
    server-captured-exit-code mechanism, in the paragraph immediately before "this file
    names them and links, and deliberately does not restate them". Rewritten to name all
    three facts without describing any. Fixed.

12. [MINOR] `docs/DISPATCH.md` — `connect_timeout` appears nowhere in it, though
    `openai_compat.py` bounds the connect phase separately (`httpx.Timeout(cfg.turn_timeout,
    connect=cfg.connect_timeout)`) and `config.py` refuses `connect_timeout > turn_timeout`
    with a `ConfigError`. A cross-field constraint between two settings is what a generated
    one-line table cannot express. **Recorded, not fixed**: this document is at its budget
    ceiling, and the rule is to trim what you are adding before raising it.

13. [MAJOR] `docs/AGENTS.md` — the frontmatter field table lists eight keys. `agents.py`
    recognises ten: `name` and `description` are absent from the table, appearing only in
    the example block. Worse, `name` carries a refusal documented nowhere — a `name:`
    disagreeing with the filename raises `AgentError`, because "a disagreeing 'name:' means
    one of the two is a lie". Rename a file and not the field and the refusal is a surprise.
    Fixed: two rows, no prose.

14. [MAJOR] `docs/AGENTS.md` — "`resolve_search_root` checks layers 1 and 2 against
    `workspace_roots`". It checks layer 1 alone. The document's own table numbers layer 1
    as workspace roots and layer 2 as the extension allowlist, matching `LAYER_ROOTS = 1`
    and `LAYER_EXT = 2`, and the function calls `_check_roots` and then returns. `paths.py`
    carried the same error in the docstring *title* of that function while its body
    explained correctly that the content layers "are applied per candidate by
    `resolve_permitted` once the walk has enumerated them". Both fixed.

15. [MAJOR] `delegate`'s MCP tool description tells the model to "pass `workdir` to bind a
    directory it can actually build or test in". The tool has no `workdir` parameter — it
    takes `task`, `effort`, `files`, `model`, `allowed_tools`, `max_tokens`, `max_turns`
    and `diagnostics`. A model following the description gets a validation error, and this
    project holds that the tool descriptions **are** the model-facing contract. Fixed by
    saying plainly that this tool takes no `workdir` and naming the one that does.

16. [MAJOR] `delegate_readonly`'s MCP tool description says "It gets `search_files` and
    `read_file`, and nothing else". It also gets `read_git`: `READ_ONLY_TOOL_NAMES` is
    derived as every registered tool with `writes` unset, and `READ_GIT` never sets it —
    confirmed at runtime as `['read_file', 'read_git', 'search_files']`. The consequence
    was not hypothetical: this description is why the audit was initially planned around a
    belief that the read-only path could not reach history. Fixed.

## Retracted

A reported claim that `docs/DISPATCH.md`'s prefix-cache measurement ("six distinct
45k-token calls moved `prefix_cache_queries_total` by 269,417, against 6 × 44,903") was
unsubstantiated. It is substantiated, in `CHANGELOG.md`. The pass was told that
`DECISIONS.md` and `JOURNAL.md` were the entire evidence base, which is a caller error: a
measurement recorded in a changelog entry for the change that introduced it is evidence.
The instruction, not the document, was wrong.
