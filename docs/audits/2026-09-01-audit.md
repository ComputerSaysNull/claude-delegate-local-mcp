# Documentation audit — 2026-09-01

Raised by the gate: 25 commits since `docs/audits/2026-08-28-audit.md`, against a threshold
of 15. No per-document drift warning fired, so nothing had gone 12 owning-code commits
untouched; the pressure was global.

Scope: every hand-written document in both planes, read against the code it owns per
`scripts/docs_ownership.toml`. Run as seven passes, five of them delegated to the local
model with the document and its owned code in one prompt. **Every finding below was
re-verified against the source in the main conversation, and every quotation was matched
with `grep` before being written down.** That check was not ceremonial — see *On method*.

The previous audit's findings were all acted on: `README.md` links rather than claims,
`docs/TROUBLESHOOTING.md:159` uses the real `hit_turn_limit` field, and every `(not built)`
marker is gone. Nothing here is a repeat.

## The dominant fault: controls that cannot fire

Three of the four blockers are the same species — a mechanism that exists, is documented,
is believed, and cannot report the case it was built for. CLAUDE.md already names this
species ("a check that cannot fail is worse than no check, because it is trusted") and
counts four prior instances. These are the fifth, sixth and seventh.

1. [BLOCKER] src/claude_delegate_local/loop.py line 1483 — docs/DISPATCH.md:233 —
   `hit_turn_limit` is false in exactly the case it exists to report. The final turn is
   built with no tools (`tools=() if _final else specs`, loop.py line 1423), so a compliant
   backend returns no `tool_uses`; the flag is `turn == turns and bool(...tool_uses)`, so
   the conjunct is false and a delegation truncated by its turn budget reports
   `hit_turn_limit: false`. It can only be true when a backend *ignores* the withdrawal —
   the opposite of the documented meaning. Three places state that meaning and all three
   are wrong about the code: loop.py line 1343, docs/DISPATCH.md:233, and
   docs/TROUBLESHOOTING.md:159, which indexes a symptom string a user will never see.
   **A test passes against it.** `tests/test_agentic_loop.py:221` scripts a backend that
   returns tool calls on both turns — including the tool-less final one — and asserts the
   flag is true. Only the misbehaving-backend path is covered; the realistic one is not.
   Likely fix `hit_turn_limit=turn == turns`, plus a regression test whose backend answers
   when offered no tools. Whether "ignored the withdrawal" deserves its own signal is a
   design call, not a cleanup.

2. [BLOCKER] scripts/docs_gate.py:697 —
   The budget check is silently off on three documents. The pattern requires `-->`
   immediately after the digits, but the convention introduced by CHANGELOG #23 records
   each raise's reason *inside* the same comment, so prose separates the number from the
   terminator and the search fails. `if not m: continue` then skips the document without a
   word, and the `SKIP` at :711 fires only when *no* document declares a budget.

       document              declares   gate sees   actual
       docs/ARCHITECTURE.md      400        no        621
       PLAN.md                   252        no        350
       CONTRIBUTING.md           210        no        226

   Negative-tested: close ARCHITECTURE's header to a single-line form and the check fires —
   "621 > 400", BLOCK. The check is disabled, not merely quiet. Fix: drop the closing
   anchor, and add a test that a document over a reasoned multi-line budget still blocks.
   Worth recording that the commit which made budget changes auditable is the one that
   stopped them being enforced; nobody removed a constraint, and no review would have seen
   it.

3. [BLOCKER] src/claude_delegate_local/server.py:811 — src/claude_delegate_local/tools.py:395 —

## On method

Five passes were delegated to the local model, with each document and the code it owns in
one prompt. It cleared four documents (`docs/MODELS.md`, `docs/AGENTS.md`, `CONTRIBUTING.md`,
`docs/TROUBLESHOOTING.md`), confirmed every empirical claim in the repository is sourced to
an ADR or JOURNAL entry, and produced finding 1 — the most valuable item here, which needed
two lines of `loop.py` sixty apart to be read together.

Some reported items did not survive verification, and the wording of the task caused most
of them: asking which "config field it restates" invites reporting fields that are correctly
*linked*, and calling docs/TROUBLESHOOTING.md a document that owns "zero facts" invites
reporting mechanisms, when its own contract at :13 forbids only "a default, a schema or a
value". Those are the auditor's fault, not the model's.

**The verification method was also wrong, and it produced a false accusation.** Four
quotations were checked with a contiguous-string `grep`, found absent, and written off as
fabricated or misattributed. Every one of them was real: they were split across a line
break, or carried inline markdown inside the phrase. A whitespace-normalised, formatting-
stripped match finds all four. `check_host_identifiers` already runs a second whole-file
pass for exactly this reason — "a name is written across a line break … far more often than
a hostname is" — so the repository had the answer and the audit did not use it. Finding 8
grew from one passage to four once the quotations were checked properly.

Two things follow. Verify a quotation the way the gate does, on normalised whitespace, never
with a contiguous `grep`. And treat any claim that a model invented something as a claim
about the checking method until the method has been tested — an audit that records a
fabrication which did not happen is worse than one that misses a finding, because it is
believed and it is unfalsifiable to the next reader.

What the evidence supports about delegation is narrower than a first pass suggested. Every
citation the model gave, across both comparison and judgement tasks, was accurate. The
judgement passes ran at low reasoning effort and the comparison passes at high, so this audit
cannot separate task type from effort and does not claim to. The defensible rule is to give
judgement work at least the effort given to comparison, and to check its output with a
matcher that tolerates line breaks.

## Recommendation

Findings 1 and 2 are each a control that cannot fire, and each wants its own commit with a
negative test — a test asserting the flag is true when a compliant backend exhausts the turn
budget, and a test asserting a document over a reasoned multi-line budget still blocks.
Neither is a one-line fix and neither should be batched with the others. Finding 3 is a
behaviour change to a model-facing string and takes a CHANGELOG entry. Findings 4 and 5 are
one edit to one sentence. Findings 6, 7, 8 and 9 batch. The budget decisions are a separate
conversation and should not be made inside a fix commit.
