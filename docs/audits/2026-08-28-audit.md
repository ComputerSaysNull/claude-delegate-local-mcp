# Documentation audit — 2026-08-28

Raised by the gate: 15 commits since `b292727`, which is the threshold the previous audit
lowered to. First time the counter has asked rather than been asked.

Scope: every hand-written document in both planes, plus the two generators, read against
`src/` and `tests/` at `9cb08f3`. Run as three scoped passes; every finding below was then
re-verified against the code in the main conversation before being written down, because an
audit is a record and a wrong entry in it outlives the pass that produced it.

M4 landed inside this window (#28, #30), and that is where almost everything here comes
from. Not because M4 was written carelessly — because **a milestone landing invalidates the
sentences that were true while it was pending**, and nothing looks for those.

## The dominant fault: text that says a built thing is unbuilt

Six places still describe M4's machinery as future work. This is the inverse of the fault
the last two audits found — describing absent machinery in the present tense — and it is
worse, because `docs/TROUBLESHOOTING.md:15` makes the claim contractual: entries marked
*(not built)* say "nothing in the server can produce them". A reader hitting a real symptom
is told it cannot happen and goes looking somewhere else.

1. [BLOCKER] README.md:11-12 — src/claude_delegate_local/server.py:334 —
   "`files[]`, the agentic loop, the sandbox and the agent roster do not [work]." `delegate()`
   dispatches through `run_agentic_loop` whenever `allowed_tools` resolves non-empty, and
   `files[]` prefetch is live. Only the sandbox and the roster are still missing. This is the
   first paragraph a reader sees.

2. [BLOCKER] docs/TROUBLESHOOTING.md:159 — src/claude_delegate_local/server.py:77 —
   Entry is titled `turn_limit` and marked *(not built)*. Three faults in one heading: the
   field is `hit_turn_limit`, so the string indexed appears in no output the reader can
   search for; the symptom is reachable today and the marker denies it; and the remedy —
   "raise `max_turns` in the agent's frontmatter" — names a control that does not exist.
   `resolve_max_turns` (loop.py:564-582) takes a call argument or `max_turns_default`.

3. [BLOCKER] docs/TROUBLESHOOTING.md:169 — src/claude_delegate_local/loop.py:795 —
   "The call disappears after about 30 minutes *(not built)*". The entry's own body says
   progress notifications exist to prevent this and that seeing it means they are not
   arriving — which is now exactly right, and exactly what the marker forbids the reader from
   believing. Same at :175. Both markers must go; neither body needs changing.

4. [MAJOR] src/claude_delegate_local/config.py:258-259 → docs/CONFIGURATION.md:134 —
   `retry_max_delay` is documented as kept low "because nothing yet emits a progress
   notification to hold that off -- that is ADR-0018 and lands with the turn loop." It landed.
   The string is a config docstring, so it renders verbatim into the generated table: **the
   gate cannot see this, because the committed file matches the generator's output exactly.**
   A generated document is only as true as the source strings behind it.

5. [MAJOR] README.md:130-132 — src/claude_delegate_local/server.py:322-331 —
   "the per-turn progress notification that answers that is M4, so until then keep one-shot
   tasks well inside it." Wired, and called once per turn. The caveat is now advice against a
   problem the code already solves.

6. [MINOR] docs/TROUBLESHOOTING.md:152 — src/claude_delegate_local/tools.py:64-81, 320-323 —
   "Tool arguments arrive malformed *(not built)*". `_text_arg` and `_int_arg` raise
   `ToolRefused`, `execute_tool` returns it as an error result, and the model gets another
   turn — which is precisely what the entry describes. Marker only. Checked because a scoped
   pass flagged it as possibly reachable-but-uncaught and wanted a human call: it is caught,
   and `test_read_file_refuses_a_non_string_path` covers it. No code fix.

## Agent frontmatter, offered twice by documents and implemented nowhere

7. [BLOCKER] docs/DISPATCH.md:129 — src/claude_delegate_local/loop.py:161-162 —
   Documented effort precedence is "agent frontmatter, then the registry row, then the global
   default." `resolve_effort` is explicit argument → registry row → global default; frontmatter
   is unstarted M6. So the documented order both invents a step and drops the real one.
   `docs/ARCHITECTURE.md:133-134` states it correctly, which makes this worse rather than
   better: two product-plane documents disagree on one fact, and **the wrong one is the owner**
   — DISPATCH.md owns `loop.py`, so it is what a careful reader trusts.

   With finding 2, that is two documents independently telling a reader to reach for M6
   frontmatter. Neither is a typo; both are a document written to the plan instead of to the
   code, and no check distinguishes those.

## A generator bug that produces a correct-looking table

8. [MAJOR] scripts/gen_config_docs.py:192-194 —
   The leftover "Other" loop omits three branches the per-section loop applies at 176-182:
   unit suffix, `**required**`, and the `**Inert.**` prefix. Live consequence today:
   `DELEGATE_STATUS_PROBE_TIMEOUT` and `DELEGATE_RETRY_MAX_DELAY` render as bare `10` and
   `20.0` while every other timeout in the file says "seconds".

   The latent consequence is the sharper one. `n_inert` at :197 counts unread fields across
   *all* rows, so an inert setting falling into "Other" would be counted in the footer and
   unmarked in its row — a table contradicting its own total, with nothing to catch it.
   None of the three current leftovers is inert, so it has not fired. Fix both loops, or
   better, place the three fields in a `SECTIONS` group so "Other" stays empty.

## Recommendation

check: `(not built)` is already a machine-readable marker, and PLAN.md already knows which
milestones are done. A gate check that fails when a *(not built)* entry's milestone is closed
would have caught four of these before they were written down. Findings 8 and 12 are separate
concerns; 9-11 batch.
