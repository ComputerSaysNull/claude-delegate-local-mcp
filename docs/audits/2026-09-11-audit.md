## Findings

1. [MAJOR] `docs/DISPATCH.md`, section "An empty answer is recovered from before it is
   reported" — "when **the model's own cap** already pinned the first budget there is no
   larger budget to retry at… where the model cap equals it the budget stage never fires".
   The code skips stage 2 when `floor > asked_budget` is false, and `enlarged` is clamped by
   `budget_ceiling` *before* `entry.cap_tokens` — so ADR-0055's deadline-derived ceiling is
   a second cause the section never names. On this deployment it is the *only* cause: the
   model cap is 65,536 and `thinking_max_tokens_floor` is 131,072, so by the document's
   stated condition the budget stage should fire, and it never does. Measured: a turn asked
   at high effort decoded 44,854 tokens and stopped at length, against a ceiling computed
   from `stall_timeout × rate × reply_budget_margin` as 44,806 — agreement to 0.1%. The
   consequence is not cosmetic: every broad high-effort delegation silently spends one full
   generation proving high does not fit, then answers at low. A reader trusting this section
   would look for a model-cap explanation that is not there.

2. [MAJOR] `src/claude_delegate_local/backends/openai_compat.py`, the `read_metrics` note —
   "being a blend over every concurrency regime since boot makes it conservative rather than
   flattering". It is conservative only when the present is quieter than the lifetime mean.
   When the cluster is busier than its own history the blend over-estimates, and that is
   precisely the fan-out case where an over-estimate is fatal rather than merely wrong. The
   metric is per-request (`vllm:request_time_per_output_token_seconds`, count over sum), so
   the direction of the error tracks current concurrency directly. Evidence is in this
   session: across a run that went from 1 to 6 concurrent delegations the reported figure
   moved 35.76 → 35.56, while seven delegations died having completed no turn at all.

3. [MINOR] `docs/DISPATCH.md` — "A turn's own duration is bounded only by `turn_timeout`".
   Each attempt is bounded by `ceiling()`, the tighter of the remaining `dispatch_timeout`
   and the no-progress `stall_timeout`; `turn_timeout` bounds the call inside the adapter's
   client as a second, independent budget. The document's own "Two deadlines" section states
   this correctly, so the word "only" contradicts it. The passage's argument — that a turn
   can outlast the client idle timer, hence keepalives — is unaffected.

4. [MINOR] `docs/DISPATCH.md` — "`on_turn_done` fires as one ends and carries what the turn
   produced". It fires only when `watch.turns` is non-empty, and `turn_cost` returns early
   when `diagnostics` is off, so the callback never fires without diagnostics. The one
   shipped caller sets `diagnostics=diagnostics or transcript.enabled(cfg)`, so the
   condition is invisible today; it is a documented seam broader than its implementation,
   and a second caller passing `on_turn_done` alone would get silence.

5. [MINOR] `docs/AGENTS.md` — "A frontmatter block is **required** — a `---` line, at least
   one key, a closing `---`. A file with no block, or with an empty one, is refused." The
   "at least one key" half is not enforced. Measured against `parse_frontmatter`: a literally
   empty block is refused, but a block containing only a blank line, or only a comment, is
   accepted and yields zero fields and an all-default `AgentSpec`. The delegated pass reached
   the right conclusion by the wrong route — it asserted the empty block matches the regex,
   and it does not.

6. [MINOR] `src/claude_delegate_local/agents.py`, module docstring — "there are five MCP
   tools and there will stay five". There are six. `docs/AGENTS.md` says six, `server.py`
   carries six `@mcp.tool` declarations, and `tests/test_server.py` asserts all six by name
   with a docstring narrating the count's history. The code comment is the stale copy.

7. [MINOR] `docs/DISPATCH.md` — the three seam conditions are attributed to ADR-0008.
   `backends/base.py` attributes the model-selection condition to ADR-0009, and ADR-0009 is
   "An explicit model registry replaces prefix matching" while ADR-0008 is the
   adapter-and-canonical-format decision. The code's citation is the correct one.

## About the audit machinery

Three findings about the runbook rather than the documents. They matter because each one
makes the audit misreport, and two of them have now done so twice.

- **The CLAIMS definition in `.claude/skills/docs-audit-dispatch/SKILL.md` names only ADR
  and JOURNAL as evidence.** Four of six CLAIMS findings this run were changelog-sourced
  measurements reported as unsourced. The 2026-09-06 audit retracted an identical finding
  and diagnosed it exactly — "a caller error: a measurement recorded in a changelog entry
  for the change that introduced it is evidence. The instruction, not the document, was
  wrong" — and then the instruction was not changed, so this run reproduced it. One of the
  four is the *same* measurement retracted last time. The definition should name
  `CHANGELOG.md` alongside the other two.

- **The concurrency guidance is backwards for this deployment.** The skill says to check the
  large-prefill bound and overlap passes. Doing so killed seven delegations. The reply budget
  is seeded from a since-boot per-request decode mean that cannot see current load, and it is
  replaced only by a *completed* turn — so a delegation whose first turn is sized for an
  idle cluster and then cannot finish never corrects the estimate, and dies at
  `stall_timeout` reporting zero turns. The controlled case: two passes of identical shape
  over identical files, dispatched in the same message, one section each — the one that
  finished while the cluster was quiet answered in one turn at high effort; its twin, still
  running when fan-out reached six, stalled. Run passes serially.

- **`effort: high` is not what a broad pass receives.** Per finding 1, a broad pass at high
  effort resolves its budget to the deadline ceiling, exhausts it on reasoning, skips the
  enlarged retry as identical, and answers at low — two dispatches for a low-effort answer.
  Narrow single-section passes do answer at high in one attempt. The per-pass effort column
  should say so rather than prescribing `high` uniformly.

## Retracted

- **Three MISSING and CLAIMS findings rest on file sets I chose badly.** `transcript_dir`
  path translation was reported as undocumented; it is documented, in `config.py`'s field
  help and therefore in the generated `docs/CONFIGURATION.md`, which I had excluded from the
  pass on the grounds that generated documents are never audited. Excluding a document from
  audit does not stop it owning a fact. `models.toml` on the layer-3 denylist was reported as
  undiscoverable; `security/secret_globs.txt` carries both the entry and its rationale, and
  the AGENTS.md table says "and more".

- **Four CLAIMS findings were substantiated in `CHANGELOG.md`** and are retracted on the
  grounds the previous audit established: the handshake timing, the `--deselect` tolerance,
  the readOnlyHint approval prompt, and the prefix-cache counter measurement.

- **A reported empty-frontmatter mechanism was wrong** even though its conclusion held. See
  finding 5.
