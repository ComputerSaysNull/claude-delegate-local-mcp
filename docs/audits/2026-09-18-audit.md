# Documentation audit — 2026-09-18

Raised by the gate: 64 commits since `docs/audits/2026-09-11-audit.md`. No per-document
drift warning fired; the pressure was global.

Scope: every hand-written document in both planes, against `config.py`, `tools.py`,
`registry.py`, `agents.py`, `paths.py`, `sandbox.py`, `loop.py`, `backends/**`,
`admission.py`, `slots.py`, `transcript.py`, `server.py`, `context.py` and `doctor.py`.
All thirteen check classes were attempted and all thirteen returned something.

**Every finding below was re-verified against source before being written down, and that
changed six of them** — three retracted, two downgraded or qualified, one remedy replaced.
One retraction was of a finding *I had already confirmed by hand*; see **Retracted**.

## Findings

1. **[MAJOR] `CONTRIBUTING.md` line 292 — a removed admission rule, still documented as
   enforced.** "At most **two** of them may be delegated passes that prefetch, and that one
   admission does enforce, by killing the rest after `admission_wait_timeout`."
   `max_inflight_large_prefills` was removed by ADR-0077 on 2026-09-13 and no such field
   exists in `config.py`. The binding rule is `max_inflight_seqs`, default 6. Both halves of
   the sentence were disproved during this audit: six prefetching passes ran concurrently,
   and eight waiters were refused on `max_inflight_seqs`, not on a cap of two.
   *Found by hand, not by a pass — the project plane has no STALE class.*

2. **[MAJOR] `admission.py` contradicts itself about how many rules the gate has.**
   Line 19, module docstring: "**Three rules, checked as one predicate.**" Line 171, class
   docstring: "The four-rule gate." Line 261, `_binding`: "or None if all four do." The
   method returns four, the fourth being `(QUEUED_RULE, live.ahead)`. One word, two
   meanings: "rule" excludes the queue-position check in one docstring and includes it in
   the other two. `docs/ARCHITECTURE.md` follows the module docstring's convention and is
   consistent with it, so the fix belongs in the code, not the document.

3. **[MINOR ×3] `README.md` explains where it should link.** Three substantive
   restatements of facts the product plane owns:
   - line 99, why `.env` and `models.toml` are gitignored — near-verbatim against MODELS.md
   - line 74, "moves an existing file aside rather than over" — ARCHITECTURE.md states the
     same rule in bold
   - lines 82-84, what `provision` builds and that the doctor fails on a stale dependency
     hash — ARCHITECTURE.md owns both

   One editorial pass replacing reasons with links, not three separate edits. `README.md`
   owns no code and is the entry point; explaining *why* is what its ownership entry says
   it does not do.

4. **[MINOR] `CONTRIBUTING.md` "Build-time agents" is 106 lines** (189-295), the largest
   section in the document, and is a chronological log of six sightings of one pattern,
   each restating the rule and its history. Trim to two representative sightings **in
   place**. The pass proposed moving the detail to `docs/audits/`; that is wrong, because
   this directory holds frozen point-in-time evidence and live examples would be buried.

5. **[MINOR] `docs/AGENTS.md` "Why agents are files" carries a tool-count chronology.**
   Lines 64-75 narrate five → seven → five → six while line 59 already states there are
   six. Cut the arithmetic, keep every reason and every ADR reference — they survive the
   trim. The wording the pass proposed is rejected: it collapses three paragraphs into one
   sixty-word sentence, which is worse prose than what it replaces.

6. **[MINOR] `CLAUDE.md`'s ownership rule omits a root the gate enforces.** It says every
   file under "`src/`, `scripts/` and `.github/`" has an owning document. `docs_gate.py`
   line 1226 also covers `.claude/`, and `docs_ownership.toml` line 48 assigns
   `.claude/agents/**` and `.claude/skills/**` to CONTRIBUTING.md.

7. **[MINOR] `docs/DISPATCH.md` line 668 quotes a number that reads as a current default.**
   "since it was found reporting "60s of 14400s" while minutes from death". 14400 is
   `dispatch_timeout`'s default. Downgraded from the MAJOR the pass filed: this is a quoted
   symptom that motivates `ends_in_seconds`, not prose asserting the default, and moving it
   to CONFIGURATION.md would delete a historical observation from the passage that explains
   a design decision. One clause — "(the ceiling at the time)" — removes the drift risk.

## Retracted

- **ARCHITECTURE.md's "three-rule gate" is not stale, and I confirmed it before it was
  overturned.** Lines 655-666 read "Three rules apply … **There were four until
  2026-09-13.** A cap on concurrent large cold prefills was removed … (ADR-0077)", and
  treat the queue as a separate mechanism. The document is current and self-consistent.
  I checked lines 119 and 768, found "three" twice, and confirmed a finding without
  reading the passage that defines the term. A later pass — one written off as truncated —
  read the surrounding paragraphs and overturned both the original finding and my
  confirmation. What survives is finding 2, which is about the code.
- **README's `--doctor` line is not a cross-plane leak.** The pass paired README's usage
  comment ("non-zero on any failure") with TROUBLESHOOTING.md's list of *what* `--doctor`
  checks. Those are different facts. It also named ARCHITECTURE.md as owner while quoting
  TROUBLESHOOTING.md, and README already links out four lines later.
- **CLAUDE.md's six blind checks are not padding.** Each is a *different* shape of check
  that cannot fail, so the list teaches recognition rather than recording history — the
  "stated reason" the class is told never to cut.

## About the audit machinery

Thirty-six calls were dispatched. Eight were refused at admission, seven died at their
reply ceiling, and twenty-one produced an answer. The diagnosis is PLAN 49-52 and JOURNAL
2026-09-17; what belongs here is what it means for running the next audit.

**Scope, not effort, is the lever — and the runbook's sizing rule stops one class short.**
Twelve broad passes at `high` returned four usable answers. Sixteen narrow passes, mostly
at `low`, returned fifteen. The runbook already says to name document sections for a STALE
pass over a large module; nothing says TOO VERBOSE over a large *document* is the same
trap, and it is worse — STALE checks claims one at a time, while TOO VERBOSE must weigh
every section against every other before it can rank one. Whole-document TOO VERBOSE
failed three times and returned nothing; naming four candidate sections answered in one
attempt at `low`.

**`empty_response` does not report failure.** Every one of the seven deaths carried
`empty_response: false`. `answer_is_reasoning`, `reasoning_exhausted` and `finish_reason`
are the fields that say so, and `output_tokens` equalling the ceiling exactly is the
signature. The runbook says an oversized pass "does not come back truncated; it comes back
empty"; one pass here came back truncated mid-sentence. PLAN 52.c.

**Asking for `high` still does not get `high`.** The runbook's note says to re-measure
before changing that column and to change it only if the step-down survives a fan-out
against fixed pricing. It survived two. JOURNAL 2026-08-27 already recorded the remedy —
"raising the budget is not the mitigation for this failure; lowering the effort is" — and
dispatching at `low` directly skipped the two wasted attempts every time.
